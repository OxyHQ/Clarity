# Clarity model IDs

Clarity owns five public product IDs. The mapping is an explicit record keyed by
ID in `packages/backend/src/lib/clarity-models.ts`; it is never inferred from a
display name, list position or sort order.

| Clarity ID | Alia profile | Reasoning |
| --- | --- | --- |
| `clarity-fast` | `profile:lite` | `instant` |
| `clarity-v1` | `profile:v1` | profile default |
| `clarity-pro` | `profile:v1-pro` | `high` |
| `clarity-thinking` | `profile:v1-pro-max` | `medium` |
| `clarity-pro-max` | `profile:v1-pro-max` | `max` |

An Alia profile is not a provider, model or deployment ID. Alia sends the
canonical request to Oxy; Oxy and Kaana select and attest the deployment. A
switch below the profile boundary must not change the Clarity response model.

`GET /v1/models` and `GET /v1/models/:id` report availability only when
`CLARITY_ALIA_AGENT_ID` is configured. Unknown IDs are rejected; no fuzzy name
matching or alphabetical fallback exists.

Provider credentials and routing are structurally absent from Clarity. The
architecture gate rejects inference SDKs, known inference-key environment
names, key stores, adapters and direct provider endpoints while allowing
unrelated product/platform credentials such as Stripe, VAPID or a future
property/geocoding service.
